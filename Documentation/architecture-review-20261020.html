1. Decoupling Frame Ingestion from Attendance Recording

src/api/cctv_server.py • src/database/audit_repository.py

Problem

The video frame pipeline (_process_cctv_frame) was iterating over active tracks on every 30 FPS frame to check in personnel, leaking business domain logic into video rendering and causing 90 redundant cache/DB checks per second.

Solution (Code Judo)

Eliminated the per-frame loop entirely. Reused the canonical AuditLogger seam which already triggers on verified identity consensus with frame cooldown, safely recording attendance asynchronously in background threads.

Benefits & Locality

Locality: Rendering pipeline has zero knowledge of attendance schedules. Leverage: 100% of attendance writes now go through verified biometric consensus. Tests run in 1.1s with zero database locks.

2. Deepening the Attendance Service (Fast-Path Cache)

src/services/attendance_service.py

Problem

The in-memory cache previously only stored a set of names, requiring dummy RECORDED responses or SQLite queries to retrieve initial check-in time and status on repeat sightings.

Solution

Upgraded the in-memory cache to a structured dictionary mapping date → {person_name: {id, status, check_in_time}}. Subsequent biometric sightings return exact preserved status and timestamps in sub-microsecond time.

3. Pluggable RosterProvider Adapter Seam

src/services/attendance_service.py

Architecture Opportunity

The attendance service previously coupled daily checklist reconciliation directly to biometric_repo. We extracted an abstract RosterProvider(ABC) seam with a default BiometricRepositoryRosterProvider and an InMemoryRosterProvider double.

Benefits & Testability

Enables plugging in university Student Information Systems (SIS), LDAP registries, or CSV class lists without touching core attendance logic. Enables 100% hermetic checklist tests without SQLite.
