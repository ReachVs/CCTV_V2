Recommendation 1 (Applied)

Decoupling Frame Ingestion from Attendance Recording

src/api/cctv_server.py • src/database/audit_repository.py
Problem & Architectural Leak
The video frame presentation loop (_process_cctv_frame) was actively iterating over all active tracks on every 30 FPS frame to check in personnel. This leaked high-level business attendance logic directly into video buffer rendering, generating up to 90 redundant cache and database inquiries every second.
Applied Solution (Code Judo)
Eliminated the per-frame loop entirely. Reused the existing canonical AuditLogger seam, which already fires only upon verified biometric consensus with a frame cooldown window. Attendance recording now triggers asynchronously in background threads with zero video jitter.

Recommendation 2 (Applied)

Deepening the Attendance Service (Fast-Path Cache)

src/services/attendance_service.py
Problem: Shallow Set Cache
The in-memory cache previously stored only a set of student names. When a verified subject was re-spotted by the camera, the service had to return a dummy RECORDED status or execute a synchronous SQLite query to retrieve their original check-in timestamp.
Solution: Deep Record Dictionary
Deepened the cache to a structured dictionary mapping date → {person_name: {id, status, check_in_time}}. Subsequent biometric sightings return the subject's preserved attendance status and arrival time in sub-microsecond (< 1μs) time with zero disk I/O.

Recommendation 3 (Applied & Verified)

Pluggable RosterProvider Adapter Seam

src/services/attendance_service.py
Architectural Seam Opportunity
Daily checklist reconciliation was previously bound directly to biometric_repo. We extracted an abstract RosterProvider(ABC) seam, with a production BiometricRepositoryRosterProvider and an InMemoryRosterProvider test double.
Academic Leverage & SIS Integration
Enables plugging in university Student Information Systems (SIS), LDAP directories, or CSV class lists without modifying attendance business logic. Tests execute 100% hermetically without requiring disk or database setup.
